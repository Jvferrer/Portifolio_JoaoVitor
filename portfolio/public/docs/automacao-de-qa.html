1. O que é automação

É um QA que não cansa: o mesmo caminho, sempre igual, dizendo passou ou falhou.

Hoje o QA abre o site, clica, preenche e anota. A automação grava esse roteiro. O robô abre o navegador e faz os cliques.

O que a automação faz e o que não faz

FazNão faz
Repete o caminho conhecido, rápidoDescobrir bug novo em tela nunca vista
Avisa quando um passo quebraJulgar se o layout ficou bonito
Roda de madrugada, sem ninguémSubstituir o olhar do QA no que é novo
Frase da reunião: não vamos automatizar o universo. Vamos ensinar um robô a fazer o caminho do sócio neste site de teste — e avisar quando quebrar.

4. Desenho da arquitetura

Homologação (front)→ Playwright→ Tela (E2E) API→ POM→ GitHub→ Relatório
site abre→ login→ plano→ pagamento→ minha conta

O front é o site do sócio. O Playwright abre esse site. Tela é o teste que clica; API é o teste que não abre o navegador.

Tela e API

CamadaPara que serveExemplo
Tela (E2E)Clicar no front, como o torcedorLogin, plano, checkout
APIPreparar dados e testar regraCriar sócio, consultar status

Pastas separadas. A API prepara o sócio. A tela prova a jornada no front. Não misturar validação de contrato HTTP dentro do teste de tela.

5. POM — o jeito de trabalhar

Trabalhar com Page Object Model é a decisão do time. É o melhor jeito de manter automação em grupo.

Sem POM Evitar

Cada QA cola o botão dentro do próprio teste. A tela de login muda e quebram dez arquivos.

Com POM Usar

O teste diz “fazer login”. O botão mora só na LoginPage. Quem conserta, conserta em um lugar.

5.1 Copie este modelo

Dois arquivos: o teste e a tela. Copie o formato — mude a rota e o texto que a tela mostra.

tests/e2e/planos.spec.ts

import { test } from '@playwright/test';
import { PlanosPage } from '../../src/pages/PlanosPage';

test('deve exibir a vitrine de planos @smoke', async ({ page }) => {
  const planos = new PlanosPage(page);
  await planos.abrir();
  await planos.deveExibirVitrine();
});

src/pages/PlanosPage.ts

import { type Page, expect } from '@playwright/test';

export class PlanosPage {
  constructor(private readonly page: Page) {}

  async abrir() {
    await this.page.goto('/planos');
  }

  async deveExibirVitrine() {
    await expect(
      this.page.getByRole('heading', { name: /plano/i })
    ).toBeVisible();
  }
}

O ponto: o teste não conhece o botão. A PlanosPage conhece. Login segue o mesmo molde: teste chama await loginPage.entrar(); e-mail e botão ficam na LoginPage.

O texto /plano/i é exemplo. No dia, abra a homologação, leia o título da vitrine e coloque exatamente o que a tela mostra.

Como o robô acha o botão

Homologação ainda não tem data-testid. O POM guarda o que a pessoa vê: nome do botão, rótulo do campo, texto da tela.

OrdemSeletor
1getByRole + nome do botão
2getByLabel / getByPlaceholder
3Texto de negócio único
4CSS curto só como último recurso, dentro do POM

O que não usar

  • XPath absoluto e cadeias de nth-child
  • Classe gerada pelo framework (hash de CSS)
  • Texto que muda por campanha ou por clube
  • Seletor copiado do DevTools direto no teste

Pedido ao Dev: data-testid nos fluxos críticos (login, checkout, cadastro) é melhoria, não bloqueio para começar.

7.1 Depois de clonar

npm ci
npx playwright install chromium
npx playwright --version

No começo, só Chromium. Firefox e WebKit ficam para depois. O último comando confirma que a máquina está na mesma versão do projeto.

7.2 O que não precisa

  • Java ou Python
  • Chrome ou Edge instalado para começar
  • Uma versão diferente por pessoa

7.3 Se a rede da empresa bloquear o download

O Playwright baixa o navegador de um CDN externo. Em rede com proxy, usar a variável antes do comando:

$Env:HTTPS_PROXY="http://proxy.empresa:8080"
npx playwright install chromium

8. Como rodar o Playwright

Abra o terminal na pasta do projeto (no VS Code: Ctrl + ') e cole o comando. Tudo começa com npx playwright.

8.1 Cola do dia a dia

Guarde estes três. Resolvem quase tudo no começo:

npx playwright test --headed --workers=1
npx playwright test --ui
npx playwright show-report
ComandoO que você vê
--headed --workers=1O navegador abre e o robô clica na sua frente. Um teste por vez
--uiPainel do Playwright: escolher o teste, ver cada passo, repetir
show-reportRelatório da última execução no navegador: passou ou falhou

Primeira vez? Rode --headed --workers=1 em /planos. Você vê o caminho. Depois use --ui para investigar falha.

8.2 Primeira vez na máquina

Só depois de clonar o repositório. Confere a versão no final: tem que aparecer 1.63.0.

npm ci
npx playwright install chromium
npx playwright --version
npx playwright test --headed --workers=1 tests/e2e/planos.spec.ts

8.3 Escolher o que vai rodar

Quero…Cole isto
Rodar tudo, sem janelanpx playwright test --workers=1
Ver o navegadornpx playwright test --headed --workers=1
Só o smokenpx playwright test --grep @smoke --workers=1
Só o críticonpx playwright test --grep @critical --workers=1
Só a APInpx playwright test tests/api --workers=1
Um arquivonpx playwright test tests/e2e/planos.spec.ts --workers=1
Um teste pelo nomenpx playwright test -g "vitrine de planos"
Listar sem executarnpx playwright test --list
Só Chromiumnpx playwright test --project=chromium

8.4 Quando falha

npx playwright test --last-failed --headed
npx playwright test tests/e2e/planos.spec.ts --debug
npx playwright test --trace on --workers=1
npx playwright show-report
ComandoQuando usar
--last-failedRepetir só o que quebrou
--debugIr clique a clique, com o navegador aberto
--trace onGravar a execução para abrir depois
show-reportAbrir o HTML e clicar no teste vermelho
show-trace pasta/trace.zipVer tela, clique e rede da falha
--repeat-each=5Ver se é flake ou bug de verdade
-xParar na primeira falha

8.5 Gravar um caminho clicando na tela

O codegen abre a plataforma. Você navega; ele escreve o código. Use para achar seletor estável, não para colar o teste pronto.

npx playwright codegen <url de homologação>

Depois do codegen: leve o seletor para o Page Object (PlanosPage) e deixe o teste só com a ação, por exemplo await planosPage.abrir().

8.6 Atalhos no projeto

Quando o package.json tiver isto, ninguém precisa decorar a linha longa:

"scripts": {
  "test": "playwright test --workers=1",
  "test:headed": "playwright test --headed --workers=1",
  "test:ui": "playwright test --ui",
  "smoke": "playwright test --grep @smoke --workers=1",
  "critical": "playwright test --grep @critical --workers=1",
  "api": "playwright test tests/api",
  "report": "playwright show-report"
}

Aí o dia a dia fica:

npm run test:headed
npm run test:ui
npm run smoke
npm run report

8.7 Erros comuns

O que apareceO que fazer
‘npx’ não é reconhecidoNode 22 não está instalado ou o terminal não foi reaberto
“Executable doesn't exist”npx playwright install chromium
“Timeout 30000ms exceeded”Botão não encontrado ou homolog lenta. Abrir o report/trace antes de mudar o teste
“strict mode violation”O seletor achou dois elementos. Ajustar no POM
Passa na máquina, falha na pipelineEspera fixa (waitForTimeout). Trocar por espera do elemento
Versão diferente de 1.63.0npm ci de novo. Não instalar Playwright por fora

Atualizar o Playwright é decisão do time, em PR: npm install -D @playwright/test@latest e depois npx playwright install. Nunca só na sua máquina.

10. Organização dos QAs

Ninguém é dono de uma arquitetura. O time divide caminho de produto, não pessoa.

FrenteO que cobre

AquisiçãoCadastro, planos, checkout

Primeira semana: os QAs revisam juntos o teste de /planos e a PlanosPage. Só depois cada um puxa o próximo caminho, copiando o POM.

Checklist operacional

  • Nunca apontar o robô para produção
  • Homologação respondendo antes de rodar a suíte
  • Primeiro verde: /planos, não login
  • Versão 1.63.0 igual à do repositório
  • Tela nova? Criar Page Object, não colar seletor no teste
  • Tag no título: @smoke, @critical ou @regression
  • Massa com e-mail único; não reutilizar sócio do colega
  • Evidência automática só na falha
  • Credencial de homologação fora do código

Conclusão

Aprovar este desenho. Com POM. Sem esperar marcação nova no site. Sem um projeto por clube. Sem vários jeitos de escrever teste.
